# 坐骑数据爬虫问题解决方案总结

## 🎯 问题确认

**问题现象**: 所有角色的坐骑数据都返回相同的值：369/1047 或 369/1077

**根本原因**: 所有角色都使用了同一个API令牌，导致API始终返回该令牌对应角色的坐骑数据

## 🔍 问题分析过程

### 1. 初步测试
- 发现所有角色都返回相同的坐骑数据
- 怀疑API不支持角色参数

### 2. 深入调查
- 测试了不同的API调用方式
- 尝试添加角色名和服务器参数
- 发现API忽略这些参数

### 3. 关键突破
通过用户提供的真实API响应数据：
```
https://webapi.blizzard.cn/wow-armory-server/api/do?api=mounts&token=YOUR_TOKEN_HERE&attr=HORDE
```

**新令牌结果**: 326/1032
**旧令牌结果**: 369/1047 或 369/1077

### 4. 结论确认
- ✅ API确实支持多角色查询
- ✅ 不同令牌返回不同的坐骑数据
- ✅ 问题根源是使用了相同的令牌

## 🛠️ 解决方案

### 方案1：多令牌管理（推荐）

#### 1.1 令牌层次结构
```
默认令牌 (fallback)
├── 服务器级别令牌 (realm-specific)
└── 角色特定令牌 (character-specific)
```

#### 1.2 配置示例
```json
{
  "tokens": {
    "default": "YOUR_TOKEN_HERE",
    "realms": {
      "arthas": "YOUR_TOKEN_HERE",
      "zuldrak": "another_token_here"
    },
    "characters": {
      "Acg-arthas": "specific_token_here",
      "Alencetr-zuldrak": "another_specific_token"
    }
  }
}
```

#### 1.3 令牌获取优先级
1. **角色特定令牌** (最高优先级)
2. **服务器级别令牌** (中等优先级)
3. **默认令牌** (最低优先级)

### 方案2：API文档规范

基于官方API文档，我们确认了：
- API端点: `https://webapi.blizzard.cn/wow-armory-server/api/do`
- 必需参数: `api=mounts`, `token`, `attr`
- 支持阵营: `HORDE`, `ALLIANCE`
- 响应格式: JSON，包含 `now` 和 `total` 字段
